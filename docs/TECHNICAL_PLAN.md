# 自行車出租行網站｜MVP 技術方案

## 目標與原則

以手機優先的公開網站呈現歡樂自行車店家資訊、車種、租借時限與價格，讓訪客送出租車需求，店家再人工確認。首版重視載入速度、搜尋可見度與容易維護；不建立即時庫存、線上付款、會員或複雜管理後台。

## 建議技術組合

- **網站框架：Astro + TypeScript**。主要內容是資訊頁，Astro 可產生靜態 HTML，降低載入成本並利於搜尋引擎讀取；需要互動的預約表單再局部加入瀏覽器端程式。
- **介面：HTML、CSS 與少量原生 TypeScript**。採響應式設計和語意化標記，先避免引入大型前端框架；若未來互動變複雜，再評估 React 等元件。
- **部署：Cloudflare Pages**。網站內容以靜態方式部署；網域、HTTPS 與部署流程在正式上線前設定。
- **需求表單：Cloudflare Pages Functions + Resend**。函式負責伺服器端驗證和寄送通知，避免把郵件服務金鑰放在瀏覽器。實作以 Resend API 為通知服務，正式使用前仍需營運方提供收件信箱、驗證寄件網域並設定密鑰。首版收到需求後仍由店家透過電話或 LINE 回覆，表單成功訊息需清楚說明「等待店家確認」，不可暗示已成立預約。
- **資料儲存：首版不另建資料庫**。只將需求通知寄到指定信箱；是否需保存、查詢或匯出，依營運流程再決定。若郵件無法滿足留存需求，再評估輕量資料庫與管理介面。
- **搜尋與成效：基本 SEO metadata、社群分享資訊及 sitemap；分析工具待隱私需求確認後選用**。追蹤表單送出量和實際成立租借數，避免收集不必要的個人資料。

## 主要資料流程

訪客瀏覽靜態頁面 → 填寫租車需求 → 瀏覽器送出至伺服器函式 → 函式驗證欄位並通知店家 → 頁面顯示等待人工確認的結果。表單涵蓋聯絡方式、日期與時間、可複選車種及各車種的租借時限與台數、備註；聯絡資料僅用於回覆需求。團體預約另提供 LINE 加好友連結。

## Electron 評估

Electron 適合需要安裝在桌面電腦上的櫃台工具，但目前產品是讓旅客從搜尋、地圖或分享連結直接使用的公開網站。要求旅客下載桌面程式會增加使用門檻，也無法取代可搜尋、可分享的網站，因此 MVP 不採 Electron。若日後店家確實需要桌面管理工具，可另做內部應用；先確認管理流程，再比較網頁後台、PWA 或 Electron。

## 上線前需確認

正式網域、實際營業時間、車款照片、路線指引、表單通知收件人及通知管道、個資告知文字，以及是否需要分析訪客或保存需求紀錄仍待確認。店名、地址、電話、Facebook、車種及租金已由營運方提供。

## 演進方向

先觀察需求量及人工確認流程。當店家需要集中查詢需求時，再增加受保護的管理介面與持久化儲存；只有在確認庫存維護流程和即時性需求後，才設計庫存管理。付款、會員與優惠功能均另行評估，不預先納入首版。
